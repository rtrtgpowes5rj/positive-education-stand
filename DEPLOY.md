# Деплой стенда Positive Education на VPS

Один контейнер: Node 22 раздаёт собранную игру и держит **общий топ** для всех планшетов в зале.
Внешних зависимостей у сервера нет. Таблица хранится в файле `board.json` на томе `/data`.

## Что нужно
- VPS с Docker и Docker Compose v2, 1 vCPU / 512 МБ хватает с запасом.
- Домен, A-запись указывает на VPS. HTTPS обязателен: так iPad без вопросов открывает игру во весь экран.
- Открытые порты 80 и 443.

## Запуск
1. Распакуйте архив на VPS, например в `/opt/pe-stand`.
2. Файл `.env` уже лежит в архиве: в нём только **отпечаток** пароля демо-режима (`ADMIN_PASSWORD_HASH`), самого пароля в архиве нет. Пароль организаторы получают отдельно.
3. Есть два варианта.

   **Вариант А — с нуля, Caddy сам выпустит сертификат:**
   ```bash
   cd /opt/pe-stand
   DOMAIN=stand.example.ru docker compose --profile caddy up -d --build
   ```
   **Вариант Б — на VPS уже есть nginx:**
   ```bash
   docker compose up -d --build        # игра слушает 127.0.0.1:8080
   ```
   Затем возьмите блок из `deploy/nginx.conf.example`. Важно: для `/api/stream` нужен `proxy_buffering off`, иначе топ на планшетах обновляется только раз в 8 секунд, а не сразу. Также нужен `X-Forwarded-For $remote_addr`: по нему работает блокировка перебора пароля.
4. Проверка:
   ```bash
   curl https://stand.example.ru/api/health      # {"ok":true,"count":0,"admin":true}
   ```
   `admin:false` означает, что `ADMIN_PASSWORD_HASH` не подхватился и демо-режим на сервере закрыт.

## Как это работает на планшетах
- Все планшеты открывают **один и тот же адрес** `https://stand.example.ru/`. Каждый сам определяет, что рядом есть сервер, и показывает общий топ. Новые результаты приходят на все экраны сразу (Server-Sent Events, запасной вариант — опрос раз в 8 секунд).
- Ник уникален во всём зале. Повторная смена под тем же ником оставляет лучший результат.
- Если Wi-Fi пропал в момент финиша, результат остаётся в очереди на планшете (`localStorage`). Он отправится сам, когда сеть вернётся, и в топе не пропадает.
- Страница организаторов: `https://stand.example.ru/top.html` — общий топ и выгрузка в Excel.

## Демо-режим и очистка топа
- Кнопка «Демо-режим» на заставке и служебное окно (**Ctrl+Shift+L**) открываются только после пароля.
- Пароль проверяет сервер (scrypt). Сервер выдаёт токен на 12 часов; при выходе из демо токен сгорает.
- Перебор пароля: 5 неверных попыток с одного IP — блокировка на 15 минут. Больше 30 неверных попыток со всех адресов — вход закрыт для всех на 15 минут (защита от перебора с разных IP).
- «Очистить топ» чистит **общую** таблицу на всех стендах. Перед каждой очисткой сервер сохраняет копию.
- «Нагенерить топ» добавляет 50 тестовых результатов, настоящие не трогает.

### Сменить пароль
```bash
docker compose run --rm stand node server/hash-password.mjs 'новый-пароль-не-короче-12-символов'
# первую строку (ADMIN_PASSWORD_HASH=...) положить в .env, затем:
docker compose up -d
```
Вторая строка (`LOCAL_HASH`) нужна только для версии без сервера, например на GitHub Pages. Она прописывается в `src/records.js`.

## Данные и резервные копии
- Таблица лежит в `/data/board.json` (том `stand-data`). Запись атомарная: файл не бывает записан наполовину.
- Резервные копии лежат в `/data/backup/`: раз в час и перед каждой очисткой, хранятся последние 200.
- Выгрузить таблицу на хост:
  ```bash
  docker compose cp stand:/data/board.json ./board-$(date +%F).json
  ```
- Откатить случайную очистку:
  ```bash
  docker compose exec stand sh -c 'ls /data/backup'      # найти *-before-clear.json
  docker compose cp ./нужная-копия.json stand:/data/board.json && docker compose restart stand
  ```

## Логи
```bash
docker compose logs -f stand
```
В логе видно: вход в демо-режим (с какого IP), неверные пароли, очистку топа.

## Без Docker
Нужен Node 20 или новее:
```bash
npm ci && npm run build
ADMIN_PASSWORD_HASH=scrypt:… PORT=8080 DATA_DIR=/var/lib/pe-stand node server/server.mjs
```
Для systemd: `Restart=always`, переменные из `.env`, пользователь без прав root.

## API (для справки)
| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/health` | статус, число записей |
| GET | `/api/board` | вся таблица `{rev, list}` |
| GET | `/api/stream` | SSE, событие `rev` при каждом изменении |
| POST | `/api/records` | результат смены `{name, score, secs, at}` |
| POST | `/api/admin/login` | `{password}` → `{token, expiresIn}` |
| POST | `/api/admin/clear`, `/api/admin/seed`, `/api/admin/remove`, `/api/admin/logout` | с заголовком `Authorization: Bearer <token>` |

Ограничения: ник — 2–14 символов (буквы, цифры, пробел, `_ . -`), очки — 0–50 000, время — до суток, до 120 запросов в минуту с одного IP.

Подделать результат запросом в обход игры технически можно: клиент в браузере не может хранить секрет. Если в зале появится запись с подозрительными очками, её удаляют через служебное окно.
